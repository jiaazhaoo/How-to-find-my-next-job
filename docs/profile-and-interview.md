# 提问层与画像层（⑥ 和 ⑤）

先做 ⑥ 再做 ⑤，顺序是刻意的。

## 一、为什么提问在画像之前

前面所有阶段只能**重排作品里已有的东西**。提问是整条链上唯一产生新信息的一步，
而且它能填上一个作品结构性填不了的洞：

> **仓库能证明你擅长什么，永远证明不了你还想不想做。**

所以 `capability_without_interest`（有扎实证据、但没有任何"没人要求时主动碰它"的痕迹）
被设成了权重最高的问题类型，不是补充项。

顺带的好处：你的回答变成新卡片之后，画像可用的材料严格多于反过来做的情况。

## 二、问题从哪来：从卡片图里挖，不是让模型想

`career questions` 的候选**全部由确定性规则产生**，每个都挂着触发它的卡片 id，
所以你能看见"它为什么问我这个"。

| 类型 | 触发条件 | 权重 |
|---|---|---|
| `capability_without_interest` | ≥2 条证据 + 有主导/高难度，但零 interest 卡片 | 3.0 |
| `unverified_claim` | 你自己宣称的**带数字**的结果，作品里找不到佐证 | 2.6 |
| `self_report_gap` | 你提过某项能力，但作品里完全没痕迹 | 2.6 |
| `ownership_dispute` | 同一技能上既是 owner 又是 observer | 2.2 |
| `dormant_strength` | 证据集中在 N 年前，之后断了 | 2.0 |
| `counter_evidence` | 卡片自带反面线索 | 1.9 |
| `interest_without_capability` | 只有兴趣，没有产出 | 1.8 |
| `difficulty_spread` | 同一技能难度跨度 ≥3 | 1.5 |
| `single_source` | 高难度但只有一处证据 | 1.3 |
| `card_open_question` | 深读时模型留下的问题 | 1.2 |

**两个筛掉大部分问题的过滤器**：答案已经在卡片里的（浪费），
以及无论怎么答画像都不变的（无信息量）。

**三重配额**：每个主题 1 个、每个**类型** 1 个、每个角度最多 2 个，默认最多 7 个。
类型配额比看起来重要——`capability_without_interest` 问两个不同技能，
纸面上是两个问题，**对回答的人是同一个问题问了两遍**。

## 三、理论依据：Savickas 的 CCI，作为角度而非题库

生涯建构访谈（Career Construction Interview）用五个提问引出职业叙事——
榜样、常看的媒体、喜欢的故事、座右铭、最早的记忆——咨询师从答案里听"生命主题"。

这里是**改编，不是照搬**：不问那五个标准问题，而是把每个候选标上它服务的 CCI 目的：

| angle | 它在挖什么 | 对应 CCI 提问 |
|---|---|---|
| `self_concept` | 你怎么看自己 | 榜样 |
| `environment` | 你被什么样的问题和环境吸引 | 常看的媒体 |
| `script` | 你觉得改变是怎么发生的 | 喜欢的故事 |
| `advice` | 你会给同处境的人什么提醒 | 座右铭 |
| `preoccupation` | 你现在没解决的是什么 | 最早的记忆 |

角度决定**追问往哪走**，也用来检查一组问题是不是失衡了——
五个问题全在挖自我概念，那就是个性格测验，而这个项目恰恰不做性格测验。

## 四、回答如何回流

`career answers` 把回答变成卡片，`source: "interview"`，quote 是**你的原话**
（所以 `career verify` 一样能核对）。

这里有条必须守住的规则，否则整个证据层会被污染：

> **回答的 `kind` 必须匹配你实际说了什么。** 描述做过的事 → `capability`/`decision`/`impact`；
> 说想不想做 → `interest`；描述自己 → `self_concept`。
> 把偏好标成能力，会悄悄抬高证据层，而且下游检测不到。

## 五、一个写测试时才暴露的漏洞

原本的规则是"≥2 个独立来源 = pattern"。但考虑这种情况：

- 你在推文里说"我把 ETL 从 6 小时优化到 40 分钟"（→ `self_concept` 卡片，来源 `x-post.md`）
- 访谈里你又说了一遍（→ 卡片，来源 `interview`）

**按来源数它是 2，按证人数它是 1。** 同一个人在两个地方说了同一件事，被系统认证成了"模式"。

现在的规则加了一条硬约束：

> **一个主题要成为 pattern，至少需要一张有工件支撑的卡片**——
> 即不是自述类型、也不是访谈来源的卡片。**否则任何说过两遍的话都能自我认证。**

访谈仍然能把 anecdote 升级成 pattern（工件 + 证词 = 真的更强），
但 0 个工件 + 证词，无论说几遍都只是证词。

## 六、画像层：骨架 + 强制引用 + 四个段落

画像是整条链上**最危险的产物**——它是会被贴进简历的那部分，
也是语言模型最乐意"润色"成恭维话的那部分。三重机制对抗这个压力：

**1. 给骨架，不给白纸。** `career profile` 用 Python 决定**什么能写**：
只有 pattern 主题能进证据段。写作阶段填文字，不选结论。

**2. 强制引用。** 证据段里每一句断言都必须带卡片 id，`career profile --check` 校验
每个 id 存在、属于 pattern 主题、且不是自述卡片。**无引用的断言是错误，不是风格问题。**

**3. 四个段落不能互相借用可信度：**

```
{{evidence}}       作品能证明的      —— 必须引用
{{self-reported}}  你自己说的        —— 明确标注
{{single-source}}  只出现过一次的    —— 明确标注
{{gaps}}           记录读不出来的    —— 不允许为空
```

这四个是四种不同的认知状态。**把它们合并，正是"我写过一个迁移脚本"
变成"资深迁移架构师"的路径。**

第四段是不常见的那个：多数画像从不说自己不知道什么，
而这恰恰是它对"下一步该干什么"没用的原因——也是提问层的原料来源。

## 七、机器管什么，skill 管什么

**代码强制**（`career profile --check`）：段落齐全、引用存在且合法、
自述不得充当证据、单一来源不得进证据段、空白段不得为空、人格特质用语直接判错。

**skill 负责判断**（写不进代码的）：证据支持多大的说法就写多大、
`role_signals` 混合时要写"主导了 X，在 Y 中是评审"、
以及最重要的一条——

> **`stance` 字段是整份文档里最有价值的东西。**
> 有扎实证据显示你擅长某事、而你明确说不想再做，就把两件事写在同一句话里，
> 不要抹平成"经验丰富且兴趣广泛"。任何只读作品的流水线都产不出这句话。

## 八、完整流程

```bash
python3 -m career questions --year 2026    # ⑥ 挖问题
# 在 CLI 里跑 /interview，它会重写措辞并逐个问
python3 -m career answers --file answers.jsonl
python3 -m career profile                  # ⑤ 生成骨架
# 在 CLI 里跑 /profile 写正文
python3 -m career profile --check workspace/09_profile.md
```

# 附：信度测量（`career reliability`）

## 它补的是什么洞

这条流水线的每条断言都可追溯，但**可追溯不等于可复现**。`deep-read` 是一次采样的模型调用，
同一个 pack 跑两遍会得到两套卡片——差多少，此前没人知道，包括我。
下游所有精度都继承这个方差，所以在拿到这个数字之前，后面各阶段的精细设计都是装饰。

## 一条决定数字有没有意义的规则

> **各次运行不能看见彼此。**

如果第二次能看到第一次的卡片——同一个上下文、同一段对话、甚至一份摘要——
**测的就是记忆不是信度**，而且会朝着好看的方向偏。这样得到的数字比没有数字更糟，因为它会被相信。

实践上：每次之间 `/clear`，或者干脆分开会话。

## 五个指标，从原材料到成品

| 指标 | 不一致意味着什么 |
|---|---|
| 引用段落 | 两次看的根本不是同一段材料——最基础的失败 |
| 主张 | 同样的段落，得出了不同结论 |
| 技能标签 | 标签不稳；下游聚类完全依赖它 |
| 主题(pattern) | 结论本身在漂移 |
| 最终问题 | 访谈会变成另一场——**这才是成品** |

**从下往上读。** 卡片层抖动是可以容忍的，只要问题层稳定——那说明聚合在吸收方差，
而"两个独立来源"这条规则本来就是干这个的。真正该警惕的是反过来：卡片稳、问题不稳，
那意味着排序在放大微小差异。

## 建这个东西时改掉的两个指标 bug

**1. 主题按标签字符串匹配。** 主题的标签是某张成员卡片的措辞，
换个说法就对不上——**和用卡片 id 匹配是同一类错误**（id 是措辞的哈希）。改成按技能集合。

**2. 技能集合精确匹配还是太严。** 两次找到同一个主题，但成员卡片差一张，
技能并集就差一个标签，于是被判成两个不同主题。改成和主张一样的软匹配（Jaccard ≥ 0.5）。

在受控扰动数据上（随机丢 20% 卡片、difficulty ±1、30% 改写措辞）：

```
引用段落      75.0%  [usable]
主张          60.0%  [usable]
技能标签      75.0%  [usable]
主题(pattern) 100.0% [stable]   ← 聚合把卡片层噪音吸收掉了
最终问题      77.8%  [usable]
difficulty 同一条主张平均相差 1.60 级，其中相差 ≥2 级的有 2 条
```

最后那行验证了审计里的第 ⑦ 条：**difficulty 这个 1-5 分没有锚点，却在驱动 `diff>=4` 的触发条件。**

对照组（三次完全相同的输入）全部 100%——**如果这个对照不是 100%，说明指标在测自己的噪音。**

## 三条必须跟着数字一起说的话

1. **这是原始重合率，没有做机会校正。** kappa 一类统计量需要一个「所有可能卡片」的全集，
   而这里的全集是「模型可能写出的任何句子」，不存在。**真实一致性只会比打印出来的低。**
2. **分档（stable/usable/shaky/unreliable）是我为这个工具定的惯例**，不是任何领域标准。
3. **N 很小。** 三次运行、一个 pack，是抽查不是估计，没有置信区间。

## 一条纪律

数字难看**不要偷偷重跑到好看为止**——那是换了个形式的 p-hacking。
先如实报第一次的结果，然后改一个具体的东西（deep-read 的指令、pack、卡片 schema），
再作为一个单独标注的结果重新测。
