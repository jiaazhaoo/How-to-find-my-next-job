# 输入层设计：脱敏与深读

这一层只解决两件事：**怎么把材料安全地交给模型**，以及**模型怎么把海量材料读得又快又深**。
画像、性格、提问都在后面的层，且都只允许消费这一层产出的、带引用的证据。

---

## 一、脱敏层：闸门必须 fail-closed

### 威胁模型

真正的风险不是"AI 会记住我的密码"，而是三件更平常的事：

1. **凭据泄露** —— 代码库里的 API key、连接串、`.env`。一旦进了对话历史、日志或缓存，你无法收回。
2. **他人隐私** —— 同事、客户、评审人的姓名与邮箱。这不是你的信息，你没有权利替他们决定。
3. **合同风险** —— 客户名、项目代号、未发布的工作。没有任何扫描器知道"北极星计划"是保密的。

第 1 类可以自动化到接近可靠；第 2 类只能部分自动化；第 3 类**必须由人声明**。
系统的设计必须让这三类的差别对用户可见，而不是假装都能自动搞定。

### 三条设计原则

**1. 闸门 fail-closed。** `redact_text()` 在替换之后会**再扫一遍**。只要还有凭据匹配，
就抛 `RedactionError`，这份文档直接被排除出语料，绝不半干净地交出去。
一个"大概率能用"的脱敏器比没有脱敏器更危险，因为它会让人放心。

```python
leftovers = self.verify(redacted)
if leftovers:
    raise RedactionError(...)   # 不返回文本
```

**2. 凭据销毁，身份假名化。** 两者处理方式必须不同：

| | 凭据 (secret) | 身份 (PII / term) |
|---|---|---|
| 替换为 | `[[AWS_SECRET_REDACTED:e2f668]]` | `[[ORG_01]]` / `[[ME_01]]` |
| 是否可逆 | **否**，明文从不落盘 | 是，映射存在 vault |
| 理由 | 存下来等于新建一个泄露面 | "谁和我一起做了什么"本身就是职业证据，抹平就毁掉了结构 |

假名是**全语料稳定**的：pack 1 里的 `[[ORG_01]]` 和 pack 7 里的 `[[ORG_01]]` 是同一家公司。
模型因此仍能推理关系，而你没有交出任何名字。你自己的身份折叠成 `[[ME_01]]`，
模型据此分辨哪些贡献是你的。

**3. vault 是皇冠上的宝石。** `workspace/vault/aliases.json` 是唯一能把别名还原成真名的文件，
权限 0600，已在 `.gitignore`。它比原始材料更敏感——它把全部人物表集中在了一个文件里。
`python -m career restore` 只在本地用它把最终报告读回真名。

### 检测规则

27 条内置规则，纯标准库，零依赖、零网络：

- **凭据**：私钥块、AWS/GitHub/GitLab/Slack/Stripe/OpenAI/Anthropic/Google/阿里云/腾讯云 token、
  JWT、连接串密码、Authorization 头、`.env` 行、通用赋值。
- **身份**：邮箱、中国身份证（带校验位）、手机号、国际号码、银行卡（Luhn）、IP、内网域名、云账号 ID。

误报控制是重点，否则报告会被噪音淹没、人就不看了：

- **熵门限**：`password = "changeme"` 不算凭据，`password = "Xk9vQ2mLz7pWr4Tt"` 才算。
- **校验位**：18 位数字必须过身份证校验，16 位必须过 Luhn，否则那只是个订单号。
- **引用识别**：`token = os.environ["GH_TOKEN"]` 是引用不是值。
- **占位符表**：`changeme` / `<your-password>` / `${SECRET}` 一律放行。

### 自动化到不了的地方（重要）

跑一遍 fixture 就能看见边界：

```
作者：[[ME_01]]  评审：Wang Fang <[[EMAIL_02]]>
```

邮箱被抓到了，**名字没有**。因为 Wang Fang 没有出现在 git 历史里，正则也不知道哪串字符是人名。
这不是 bug，是这一类工具的固有边界。三个补救层，成本递增：

1. `sensitive_terms` —— 你自己声明，最可靠，一行配置。
2. `pseudonymize_git_identities` —— 自动收割 git 历史里所有同事的姓名与邮箱（默认开）。
3. Presidio（可选）—— NER 识别人名/机构/地点，能兜住散落在正文里的名字。

所以 `redaction-review` 这个 skill 存在的意义是：**强制你亲眼看一遍第一个 pack**。
自动化负责规模，人负责那些机器不可能知道的东西。

## 二、深读层：漏斗 + 证据卡片

### 为什么不是"把所有东西塞给长上下文模型"

塞得进去不等于读得进去。四十个仓库摊平了喂给模型，得到的是一段谁也没法核对的漂亮总结，
而其中最讨好你的部分，通常正是编的。两个具体问题：

- **信噪比**：仓库里 90%+ 的字节是依赖、锁文件、构建产物、生成代码。它们和"你是谁"无关。
- **不可证伪**：没有引用的结论无法检查，模型的幻觉和你的真实成就长得一模一样。

### 漏斗：四步，前三步不花 token

```
① 扫描 (0 token)     万级文件 → 千级        排除 vendored/生成/二进制/重复
② git 事实 (0 token) 每个文件的 ownership   一次 git log --numstat 走完全仓
③ 分诊 (0 token)     千级 → 百级            信号打分 + 预算 + 多样性配额
④ 深读 (花 token)    百级 → 证据卡片        只在高密度材料上花模型
```

fixture 上的实测：46 个文件 → 保留 3 个（422KB → 1KB，0.3%）。真实仓库上这个比例更极端。

### 分诊：什么叫"高信号"

得分由四部分构成（见 `career/triage.py`）：

- **文档类别先验**：ADR / RFC / 复盘 (×3.0) > 报告 (×2.6) > README (×2.4) > 源码 (×1.0) > 测试 (×0.5) > 配置 (×0.35)。
- **判断语言密度**：中英双语标记——`因为/权衡/取舍/放弃了/根因/教训` / `because/trade-off/instead of/root cause`。
  **人在解释一个选择的地方，就是职业证据密度最高的地方。**
- **量化结果密度**：`P99 / 降低 35% / 2.4 倍 / 800ms`。有数字的成就和没数字的成就，价值差一个量级。
- **你的所有权**：`my_line_share` 来自 git，不是来自语气。别人写的文件不该变成你的画像。

### 预算与多样性配额

直接取 top-N 会失真：一个 monorepo 里 300 个 markdown 会把预算吃光，
于是"你"就变成了那一个项目。所以加了两条配额：

- 单个仓库最多占预算 40%
- 单个文档类别最多占 45%

配额跑完如果预算还有剩，再放开贪心填满——此时每个"少数派"来源都已经有过机会了。

### 结构化摘录：长文件不截断，而是收缩

超出预算的文件不会被"砍到前 N 字"（那会正好砍掉写在结论里的东西）。
`triage.excerpt()` 保留：开头、所有标题/函数签名、所有判断标记和数字结果所在行及其上下文，
其余折叠成 `... [N lines elided] ...`——**并且明确告诉模型这是收缩，不是文件结束**。

实测：2797 token 的文件收缩到 559 token，决策句一句没丢。

### 证据卡片：让"深刻"变成可检查的

深读的产物不是摘要，是卡片。每张卡片是一个**可被证伪的单点主张**：

```json
{"claim":"设计并落地了支付网关迁移的双写+对账灰度方案","kind":"decision",
 "evidence":[{"source":"3e81e5b2","locator":"决策段","quote":"我们决定用双写 + 对账做灰度，因为一次性切换无法回滚"}],
 "skills":["migration","data-consistency"],"role_signal":"owner","difficulty":4,
 "confidence":0.85,"counter_evidence":"","open_question":"三方案对比是你独立做的，还是团队已有的结论？"}
```

三条机制让它保持诚实：

1. **引用必须真实存在。** `python -m career verify` 逐条把 quote 拿回模型当时看到的摘录里比对。
   fixture 里那张编造的"独立完成三地容灾演练"卡片，被当场抓出来。
2. **禁止人格推断。** claim 里出现"内向/性格/完美主义/MBTI"直接判为校验错误。
   理由不是价值观，是信度：2025 年的实证研究里，LLM 从真实对话推断大五人格，
   所有维度相关系数低于 r≈0.30。行为+证据是可靠的，特质标签不是。
   人格如果要进画像，只能来自你亲自填的正式量表（IPIP-NEO / RIASEC），不能来自模型读你的代码。
3. **一次不算数。** 单一来源支撑的主张标为 `anecdote`，只有 **≥2 个独立来源**才升级为 `pattern`。
   画像只能用 pattern 写；anecdote 留在原地，变成问题。

### 矛盾就是问题

`python -m career themes` 除了聚类，还输出 `tensions`——记录里自相矛盾的地方：

```
? 在自研 vs 采购的决策中主张自研，依据是三年 TCO 差 2.4 倍
    vs 报告有评审人，结论不一定由你独立得出
? role varies across migration: ['observer', 'owner']
    vs same skill appears with different levels of ownership
```

这正是下一层"因人而异地提问"要的原料：**问题不该来自题库，该来自你材料里说不通的地方。**
每张卡片的 `open_question` 字段同理。

## 三、连接器：只导入，不读取

### 一条不能让步的规则

> **连接器唯一的职责是把内容落成本地文件**，放进 `workspace/00_staging/<connector>/`，
> 然后交给已有的 scan → redact → triage 流水线。分析时绝不实时去拉数据。

理由第一条是硬的：**脱敏必须只有一个入口**。一条 live API 路径 = 一条绕过 `redact`
直达模型的路，这个洞开了，前面的 fail-closed 全部作废。另外两条：可复现（重跑 prep
不用重新拉，别名保持稳定）；以及现实——X / LinkedIn 现在基本只给打包导出，API 那条路本来就走不通。

staging 目录会被 `scan` 自动纳入，`source_type` 从路径反推（`00_staging/claude-code/` → `chat`），
下游据此做配额和分诊，不需要额外传状态。

### 已实现：本地 Claude Code 会话日志

排第一，因为它提供了别处买不到的东西：**仓库记录什么上线了，会话记录你试过什么。**
放弃的方案、你不得不问的问题、你跟模型吵架的地方，没有一样会进 commit。

两个额外性质：

- **天然和工作对齐**：每条记录带 `cwd` 和 `gitBranch`，会话就贴在它产出的提交旁边。
- **无义务**：没人指派你周日晚上问那个问题，所以话题分布是**揭示性偏好**，不是自评。

提取的难点在信噪比：一个 315 条记录的会话里，人类回合大约 5 个，其余 98% 是 tool_result、
thinking 和队列操作。适配器的做法是——**人类回合逐字保留，助手散文压缩成 600 字上下文桩，
工具流量降维成一行计数**。sidechain（子 agent 自言自语）整体排除。

### 聊天记录带来的两个新问题，已经处理

**1. 配额会被击穿。** 一年的会话日志按体量能压过所有仓库之和，画像会变成"一个爱和 AI
聊天的人"。所以在仓库配额、类别配额之上又加了一层 **source_type 配额**（默认 35%）。

**2. 分诊规则完全不同。** 文档靠"决策词密度"，但在会话里那主要衡量的是**助手**。
会话的高信号是：

- **pushback（你推翻模型的次数）** —— 最强信号。**你没法跟模型争论一个你不懂的领域。**
- teaching（你向模型解释背景的长度）
- 你自己打的字数、多轮深度

而且只对 `## you` 段落打分和摘录。超预算时**永不截断人类回合**，先扔助手桩。

顺带修掉一个隐蔽偏差：阈值原本按字符数算，200 个英文字符是一句话，200 个汉字是一大段。
现在按信息量加权（CJK ×2.5），中英文用同一个阈值。

### 主题切除：聊天记录需要的第二层策略

聊天记录里有健康、钱、律师、别人粘给你的东西。**这些段落里根本没有可脱敏的标识符**——
问题不是"有 PII"，而是"这段话不关职业画像的事"。所以 chat 类材料在脱敏之后再过一层主题策略：

- 命中健康/财务/法律/私人话题的**单个回合**被切除，留下可见标记（模型必须知道有东西被拿走了，
  否则它会把剩下的回合当成完整对话读）。
- 只有当超过一半的块被切除时，才整份丢弃。
- 默认只对 `source_type=chat` 生效——一个仓库文件提到"药物"，很可能因为它就是个医疗产品。

另外：单份文档里出现 20 条以上凭据，判定为 key dump 整份丢弃——那不是工作样本。

### 自我吹捧回路（最重要的一条）

聊天记录里全是你对自己的描述。如果这些进了画像，AI 就是**把你的自我认知加上引用还给你**——
看起来证据确凿，实际上是一面镜子。这是引入聊天记录最大的风险，所以在卡片层写死：

> 你对自己的陈述 = `self_concept` 卡片，**永远不能算作 `capability`**，
> 也**永远不能升级成 pattern**——自我描述重复一百遍也不是佐证。

`self_concept` 是唯一允许出现特质词的卡片类型，因为它**引用**而不**推断**。
而且它有明确用途：自我概念正是 Savickas 那套叙事访谈要挖的东西，
**你的自述和你的作品之间的落差**，是整个系统里最好的提问发生器。

## 四、不做什么

- 不判断你的性格。
- 不给职业建议。
- 不把材料上传到任何地方——这一层全部在本地跑，模型调用由你的 CLI 发起，你决定用哪个模型。
- 不假装脱敏是完全自动的。第一个 pack 你必须自己看一遍。
